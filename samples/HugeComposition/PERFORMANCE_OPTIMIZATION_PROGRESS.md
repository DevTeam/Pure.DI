## Rules for updating this log

1. Mark an iteration `Measuring`, `Investigating`, `Implemented`, `Accepted`, or `Rejected`.
2. Link only reports collected on the same machine and the same source revision.
3. Record the compared median change and run-to-run spread in the local iteration notes or commit message, not as a permanent cross-machine expectation.
4. Run the standalone build and relevant unit tests for every candidate. Run `tests/Pure.DI.IntegrationTests` periodically before accepting a notable series of changes, and earlier only when a candidate changes integration-sensitive behavior; do not run it for every optimization iteration.
5. When a change is rejected, record the reason and move to the next hotspot without deleting the evidence.
6. Reject changes that materially complicate a hot path unless profiling demonstrates a substantial, repeatable local benefit.
