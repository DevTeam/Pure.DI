# Pure.DI - what is new

Version **2.5.8**, compared with the 2.5.7 tag: 103 commits and 34 closed issues.

## 1. Generated code grows with the graph, not with the number of paths through it

Graphs with delegates and cycles could still make the generated code and the build time grow with every path that leads to a dependency. This release removes most of the remaining sources of that growth.

- The graph under a `Func<T1, T>` delegate is rewritten once per override scope instead of once per dependency path, including nested delegates, back-references and inner delegates that pass the same argument again. Fixes [#172](https://github.com/DevTeam/Pure.DI/issues/172), [#175](https://github.com/DevTeam/Pure.DI/issues/175), [#176](https://github.com/DevTeam/Pure.DI/issues/176), [#177](https://github.com/DevTeam/Pure.DI/issues/177) and [#178](https://github.com/DevTeam/Pure.DI/issues/178).
- An object made by the lambdas of a delegate is created by a local function instead of being repeated in every lambda, and a singleton reached inside delegates with arguments is created in one place. Fixes [#184](https://github.com/DevTeam/Pure.DI/issues/184) and [#186](https://github.com/DevTeam/Pure.DI/issues/186).
- Screens that open each other through delegates, a typical navigation graph, are created once by local functions instead of once per navigation path, also when they use an instance that a singleton uses too and when a `PerBlock` instance is under their factories. Fixes [#192](https://github.com/DevTeam/Pure.DI/issues/192), [#195](https://github.com/DevTeam/Pure.DI/issues/195) and [#201](https://github.com/DevTeam/Pure.DI/issues/201).
- Arrays and spans, transient diamonds that share a `PerBlock` dependency and `IAsyncEnumerable<T>` dependencies no longer multiply the code either. Fixes [#187](https://github.com/DevTeam/Pure.DI/issues/187), [#188](https://github.com/DevTeam/Pure.DI/issues/188) and [#189](https://github.com/DevTeam/Pure.DI/issues/189).
- A transient instance made by a factory is created by a local function when that keeps the code smaller, unless the factory reads `ctx.ConsumerType` or `ctx.ConsumerTypes`, since then each consumer needs its own copy.

## 2. New diagnostic: the code of a root is much larger than its graph

The new `DIW016` warning is reported when the code of a root has at least 2,000 lines and more than 50 lines per dependency. It points at the cases that are still expensive by design, such as a transient dependency reachable from itself through `Lazy<T>`, or the arguments of nested delegates that are overridden for every object created under them.

- Give such a dependency a shared lifetime (`PerResolve`, `PerBlock` or `Singleton`) when it does not need to be a new instance each time, or set `Hint.LocalFunctions` to `On`.
- When the argument of a delegate is needed only by the object the delegate creates, bind the delegate yourself with `ctx.Let` instead of `ctx.Override`.
- See [`DIW016`](https://github.com/DevTeam/Pure.DI/blob/master/DIAGNOSTICS.md#diw016) for details.

## 3. Scopes and singletons

- The singletons of a composition are now stored in one object that the root composition shares with its scopes, so creating a scope no longer allocates and clears a field for every singleton of the composition.
- A scope creates its array of disposables only when it creates its first scoped disposable instance, and disposing a scope no longer allocates a new array.
- With Microsoft DI, every root except a singleton is now resolved from the composition of the current scope. A transient, per-resolve or per-block root with a scoped dependency used to take that dependency from the parent composition, so it lived for the whole application. Closes [#43](https://github.com/DevTeam/Pure.DI/issues/43).
- A shared instance is checked once more under `ctx.Lock` when thread safety is disabled. Fixes [#174](https://github.com/DevTeam/Pure.DI/issues/174).

## 4. Finding implementations

- `Roots` and `Builders` take a new optional `searchInCompilation` parameter. When it is `true`, the implementations are looked up in every type of the current assembly, so a setup works without importing the namespaces of the implementations. Fixes [#153](https://github.com/DevTeam/Pure.DI/issues/153).
- When a wildcard filter matches nothing, `DIE016` now names up to five implementations that exist in the assembly but are not visible from the setup, and suggests a `using` directive or the new parameter.
- An interface re-implemented on top of a base class is kept as a contract of a simplified binding. Fixes [#173](https://github.com/DevTeam/Pure.DI/issues/173).
- The consumer type scenario now explains that the `TT` marker substitutes the consumer type at generation time, so a call such as `CreateLogger<TT>()` needs no runtime value. Closes [#77](https://github.com/DevTeam/Pure.DI/issues/77).

## 5. Fixes in factories, overrides and generated code

- A singleton that reads a member of another singleton no longer gets `null` because the other singleton was not created yet. This was a regression in 2.5.7. Fixes [#202](https://github.com/DevTeam/Pure.DI/issues/202).
- A singleton that reads a delegate argument on a cycle through lambdas compiles again. This was a regression in an earlier fix of this release. Fixes [#193](https://github.com/DevTeam/Pure.DI/issues/193).
- A nested delegate creates its result instead of returning the argument of an outer delegate. Fixes [#185](https://github.com/DevTeam/Pure.DI/issues/185).
- A `Func<T1, T>` injected by a factory that overrides `T1` gets its own argument, and the override of a factory replaces the inherited one. Fixes [#183](https://github.com/DevTeam/Pure.DI/issues/183).
- The argument of `ctx.Let` reaches the instance behind a decorator; this is now covered by tests. Closes [#191](https://github.com/DevTeam/Pure.DI/issues/191).
- When locals of a factory are renamed:
  - type names in an override value are no longer renamed (CS0103), fixes [#179](https://github.com/DevTeam/Pure.DI/issues/179);
  - two factories that override the same type under one root both declare their value (CS0103), fixes [#180](https://github.com/DevTeam/Pure.DI/issues/180);
  - named arguments and members keep their names (CS1739), fixes [#197](https://github.com/DevTeam/Pure.DI/issues/197) and [#198](https://github.com/DevTeam/Pure.DI/issues/198);
  - a local no longer takes the name of a lambda parameter that `ctx.Let` passes (CS0136, CS0841), fixes [#199](https://github.com/DevTeam/Pure.DI/issues/199);
  - variables and roots get unique names when the name of a type ends with a number.
- A `return` in a local function or an anonymous method of a factory is no longer rewritten as a return of the factory. Fixes [#200](https://github.com/DevTeam/Pure.DI/issues/200).
- A type nested in a generic type keeps the type arguments of its containing type when a generic binding is closed with it. Fixes [#196](https://github.com/DevTeam/Pure.DI/issues/196).
- Variables restored by nested custom accumulators are declared when leaving nested scopes. Fixes [#190](https://github.com/DevTeam/Pure.DI/issues/190).
- Binding ids no longer overflow when a bound type has exported members, which caused a bogus cyclic dependency and unresolved dependencies. Unused exported roots and members no longer trigger `DIW003`. Fixes [#194](https://github.com/DevTeam/Pure.DI/issues/194).
- Optional parameters:
  - an optional parameter uses its default value for each consumer and is no longer reported as unresolved when another dependency is missing, fixes [#182](https://github.com/DevTeam/Pure.DI/issues/182);
  - its value no longer depends on whether another class requires the same unbound type, fixes [#203](https://github.com/DevTeam/Pure.DI/issues/203).

## 6. Platform

- The repository builds with the .NET 11 SDK and the Roslyn 5.12 compiler toolset, and union types work on .NET 11.
- NuGet packages are now published from a version tag by a GitHub workflow that validates the package identities and smoke-tests the templates. CI builds and tests each supported Roslyn version in parallel.
